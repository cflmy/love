````md
# QDQC Cinematic Web Experience Skill
Version: 1.0

## Mission

You are not building a normal marketing website.

You are building:

> QDQC · 鹊渡情长
> An interactive cinematic love story.

The website must feel like:

- an interactive Oriental love movie
- a living digital painting
- a scroll-controlled cinematic experience
- an illustrated love book with depth
- a 3D spatial world

It must NOT feel like:

- a PowerPoint presentation
- a normal landing page
- a sequence of fade-in sections
- a collection of cards
- a generic SaaS website
- a template website
- a page with a Three.js background added to it

The user's supplied visual assets are the primary art direction.

DO NOT replace supplied assets with generic CSS shapes,
generic gradients, stock illustrations, emoji,
random 3D models, or placeholder graphics unless explicitly requested.

The implementation must make the supplied assets feel alive.

---

# 1. CORE EXPERIENCE PRINCIPLE

The fundamental rule:

SCROLLING IS NOT PAGE NAVIGATION.

SCROLLING IS CAMERA MOVEMENT THROUGH A WORLD.

Bad:

scroll
→ section changes
→ fade in
→ fade out

Good:

scroll
→ camera moves
→ foreground objects move faster
→ background moves slower
→ objects rotate subtly
→ depth changes
→ lighting changes
→ particles respond
→ typography enters the scene
→ sound changes
→ scene transforms into the next scene

Every important scroll section must feel like a shot in a film.

---

The site is a continuous world.

A chapter is a sequence of cinematic shots.

A shot is controlled by scroll progress.

Example:

0.15 - 0.30

# 4. ABSOLUTE RULE:
# DO NOT BUILD "SMOOTH SCROLL WEBSITE"

The following implementation is considered insufficient:

scroll:
    transform: translateY(...)
    opacity: ...
    transition: ...

or:

while scrolling:
    element.style.transform = ...

This produces a presentation-like website.

The implementation MUST include multiple simultaneous motion systems.

At least 3-5 visual layers must move independently.

Example:

Background:
parallax factor = 0.10

Far mountains:
parallax factor = 0.18

Middle mountains:
parallax factor = 0.32

Bridge:
parallax factor = 0.55

Character:
parallax factor = 0.75

Foreground particles:
parallax factor = 1.10

Camera:
independent movement

This creates actual spatial depth.

# 5. PARALLAX DEFINITION

"Parallax" does NOT mean:

translateY(-100px)

It means:

different objects respond differently to the same camera movement.

Every scene must define:

depth
position
rotation
scale
scrollMultiplier
opacity
blur
z
cameraOffset

Example:

```ts
type SpatialLayer = {
  id: string

  depth: number

  basePosition: [number, number, number]

  scrollMultiplier: number

  rotation?: [number, number, number]

  scale?: number

  opacity?: number

  blur?: number
}
````

Example:

```ts
const layers = [
  {
    id: "moon",
    depth: -20,
    scrollMultiplier: 0.05
  },

  {
    id: "far-mountain",
    depth: -12,
    scrollMultiplier: 0.12
  },

  {
    id: "near-mountain",
    depth: -6,
    scrollMultiplier: 0.25
  },

  {
    id: "bridge",
    depth: -2,
    scrollMultiplier: 0.55
  },

  {
    id: "butterfly",
    depth: 1,
    scrollMultiplier: 0.85
  },

  {
    id: "foreground",
    depth: 4,
    scrollMultiplier: 1.2
  }
]
```

The user should visually perceive depth even if the assets are 2D.


* reveal
* focus shift
* perspective change

# 13. SCROLL PROGRESS

Each scene has normalized progress:

0 → 1

But do NOT simply map:

progress → opacity

Instead:

progress controls multiple parameters.

Example:

```ts
cameraX = lerp(-2, 2, progress)

cameraZ = lerp(12, 7, progress)

butterflyX = bezier(progress)

butterflyY = sin(progress * PI) * 2

bridgeGlow = smoothstep(0.7, 0.9, progress)

particleDensity = remap(progress, 0.4, 0.9, 0.2, 1)

textOpacity = reveal(progress)
```

One scroll progress should drive the whole scene.

# 15. MOTION MUST HAVE INERTIA

Important visual objects should not always follow the scroll perfectly.

100

100

92

97
99

Use damping / lerp.

Example:

```ts

```

Different objects use different damping.

Butterfly:
0.06

0.02

Camera:
0.04

Foreground:
0.10

This creates temporal depth.

# 16. "TIME-LAG PARALLAX"

QDQC specifically requires time-lagged movement.

There are TWO different meanings of parallax:

Spatial parallax:
different depth layers move differently.

Temporal parallax:
different objects respond with different delays.

Use BOTH.

Example:

User scrolls rapidly.

Foreground:
responds immediately.

Bridge:
slightly delayed.

Mountain:
very delayed.

Cloud:
continues drifting.

Butterfly:
follows a curved trajectory.

This is what makes the scene feel alive.

* it scrolls

### Camera

### Parallax

Layers have different spatial response.

### Temporal lag

At least some objects have different response timing.

### Subject motion

Characters/creatures move naturally.

### Environment

Background is not static.

### Transition

Scene enters and exits spatially.

### Typography
